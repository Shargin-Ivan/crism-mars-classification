# Запуск из автономной копии

Команды выполняются из корня комплекта. Для просмотра сохранённых результатов достаточно файлов в `results/`. Для вычислений нужен полный каталог `workspace/`, для инференса обученных моделей также нужен `weights/`. Все три сцены используют собственную спектральную калибровку. Новый запуск записывается в отдельный каталог.

## Получение файлов

**Физический комплект.** Перенесите каталог целиком на другой диск или машину. В нём уже находятся обе исходные сети, калибровки, три наблюдения, обучающие спектры Plebani, кубы NF и UP с разметкой и готовые выборки. Входные файлы общие для трёх конфигураций. После установки зависимостей вычисления выполняются без сети.

**Копия из Git.** Получите бинарные файлы LFS и восстановите внешние данные. Команда для LWNet обращается к закреплённой версии авторского репозитория, только если локальных файлов нет или они отличаются. Каталог `delivery/` в примере содержит части данных, полученные от владельца физического комплекта.

```bash
git lfs install --local
git lfs pull
python restore_lwnet.py
python data_parts.py restore delivery
python package_workspace.py verify
```

Для подготовки частей на стороне владельца используйте `python data_parts.py pack delivery`. Передайте **все файлы** получившегося каталога вместе с исходниками и весами. Каждый файл занимает не более 512 МиБ. Одинаковые входы передаются один раз. Восстановление сверяет SHA-256 и по возможности использует жёсткие ссылки внутри каталога назначения. Список внешних данных находится в `large_inputs.json`, их размеры и SHA-256 — в `workspace/input_inventory.json`. Для копии без частей и LFS-объектов полноценный расчёт потребует их получения. Для передачи через GitHub Releases части прикладываются к выпуску отдельно с учётом условий источников данных.

Git LFS хранит исходный N2N4M и RobustScaler, а также обученные файлы `.pt` и `.ts`. Скрипт `restore_lwnet.py` восстанавливает отдельно исходный класс LWNet и Salinas_model.pkl из версии `ca8361cd4a1c6418e3366fcc2ebc91fb72ac8c78`. Сведения об источниках и условиях использования приведены в [SOURCES.md](SOURCES.md).

## Окружение и проверка

Для воспроизведения кампаний использовались Linux x86-64, одна NVIDIA H100 NVL и PyTorch 2.6.0 с CUDA 12.4. Используйте Python 3.11 или 3.12 и совместимый драйвер NVIDIA. Для CPU-проверки допустима сборка PyTorch для процессора.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --index-url https://download.pytorch.org/whl/cu124 torch==2.6.0
python -m pip install -r requirements.txt
python -m pip check
python package_workspace.py verify
sha256sum --check weights/SHA256SUMS
python check_weights.py
python -m unittest test_release
python run_experiment.py check
python run_experiment_50.py check
(cd workspace && python -m unittest discover -s tests)
```

Проверка весов загружает на CPU обе исходные модели, восемь лучших экспортов двух кампаний и четыре последних checkpoint кампании 50+50. Она сравнивает веса экспорта с лучшим checkpoint и выполняет один прямой проход с синтетическим входом. При чтении исходного RobustScaler библиотека scikit-learn 1.9.1 сообщает о сериализации в версии 1.2.2. Адаптер сверяет SHA-256 и проверяет 350 центров и масштабов. Команды `check` проверяют реальные выборки всех четырёх этапов. Сообщение о том, что этап HyMars ожидает лучший checkpoint Plebani, штатно для новой кампании. Отдельная проверка профиля работает без полного инференса, например `python infer.py --weights 25 --scene hymars_hc --device cpu --check`.

## Инференс с готовыми весами

Три команды ниже выполняют четыре ветви на HC. Значение `standard` включает опубликованные N2N4M и LWNet Salinas. Значения `25` и `50` используют лучшие checkpoint после этапа HyMars соответствующей кампании. При этом библиотека MICA и порог SAM (0,15 рад) одинаковы.

```bash
python infer.py --weights standard --scene hymars_hc
python infer.py --weights 25 --scene hymars_hc
python infer.py --weights 50 --scene hymars_hc
```

Для остальных двух сцен используйте `--scene frt00019468_mtrdr` и `--scene hrl000120cd_mtrdr` с каждым значением `--weights`. Пример полного цикла по девяти комбинациям:

```bash
for weights in standard 25 50; do
  for scene in hymars_hc frt00019468_mtrdr hrl000120cd_mtrdr; do
    python infer.py --weights "$weights" --scene "$scene" || exit 1
  done
done
```

По умолчанию используется `cuda:0`. На совместимой NVIDIA с меньшей памятью начните, например, с `--lwnet-batch 4 --n2n4m-batch 16` и уменьшите до 1 при нехватке памяти. Для одиночного инференса доступен `--device cpu`. Это может занять существенно больше времени. Карты и отчёт создаются в `outputs/<weights>/<scene>/`; последняя строка команды содержит путь к HTML. На HC рассчитываются показатели по фиксированной разметке, для двух MTRDR — покрытие, отказы и согласие ветвей.

## Воспроизведение обучения

Следующие команды запускают вычисления на Linux. Сначала выполните 25+25, затем 50+50 **в той же копии каталога**. Оригинальные образцы весов из `weights/` используются самостоятельным инференсом. Новые результаты имеют собственные каталоги в `workspace/finetuning/storage/`.

```bash
python run_experiment.py run
python run_experiment_50.py run
```

Первая кампания выполняет на трёх кубах исходный инференс, для каждой сети обучает Plebani350 (25 эпох), затем HyMars NF/UP (25 эпох) и повторяет инференс. Вторая обучает новые модели по 50 эпох на каждом этапе с той же исходной инициализацией. Для сравнения она проверяет завершённую первую кампанию, читает её исходные карты SAM, маски и показатели. Поэтому копирование только `weights/25/` не заменяет `main/campaign.json` со связанными файлами. После начала вычислений сохраняйте расположение рабочего каталога: журналы новых запусков фиксируют абсолютные пути текущей машины. Для прерванного запуска повторите ту же команду.

В режиме H100 результаты находятся в `workspace/finetuning/storage/h100_campaign/main/` и `epochs50/` рядом с ним. Для запуска на другой совместимой NVIDIA в Linux выберите отдельный профиль для **обеих** кампаний:

```bash
export CRISM_GPU_PROFILE=portable
python run_experiment.py check
python run_experiment.py run
python run_experiment_50.py run
```

Чтобы воспроизвести только 50+50, используйте сохранённую базу сравнения из оригинального эксперимента H100. Каталог `reference25/` содержит проверенные по исходному журналу маски, таблицы и контрольные суммы исходного SAM. Команда сравнивает их с новым прогоном и складывает результаты отдельно в `epochs50_frozen_reference/`. Этот путь доступен с обоими профилями GPU.

```bash
python run_experiment_50.py check --frozen-reference
python run_experiment_50.py run --frozen-reference
```

Профиль `portable` использует отдельный каталог `workspace/finetuning/storage/h100_campaign_portable/`, одну доступную CUDA-карту и уменьшенные батчи. При нехватке памяти в обучении этап повторяется с меньшим батчем вплоть до 2. Рабочий ориентир — 24 ГБ VRAM и 64 ГБ оперативной памяти. Фактическая потребность и длительность зависят от сцены, GPU и окружения; значения для этого профиля требуют измерения на целевой машине. Изменение батча может изменить обучение. Для возврата к исходной конфигурации в Bash выполните `unset CRISM_GPU_PROFILE`. На H100 можно также использовать `bash start.sh` и после завершения `bash start_50.sh` для автоматической подготовки и запуска.

## Что хранится в весах

В `weights/{25,50}/{lwnet,n2n4m}/{plebani350,hymars_full}/` лежат `training.json`, `normalization.json`, `result.json`, лучший `best_epoch_XXXX.pt` и соответствующий `model.ts`. У кампании 50+50 дополнительно сохранён `last.pt` каждого этапа. Номер выбранной эпохи, SHA-256 checkpoint и TorchScript записаны в `result.json`. Для HyMars сохранены три привязки в `bundles/`: идентификатор сцены находится в `preprocessing.json`, спектральная ось — в `bundle.json`, коэффициенты — в `scaler.npz`. Все пути и хеши опубликованных весов перечислены в `weights/SHA256SUMS`. Исходные манифесты `training.json` сохраняют исторические относительные пути обучающей кампании.
